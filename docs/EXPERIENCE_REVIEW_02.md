# 体验评审 02：让探索和行动产生结果

日期：2026-09-07。基线：0.9.1，提交 `4ed00b2`。

本次是评审与迭代建议，未修改运行时代码。实机观察范围为当前约 397×834 的内置浏览器、DAY 01 出生区、背包与日志；八关结构、奖励、危险和动作系统通过源码审查及内存中的只读数据检查核对。没有重新进行八关完整真人通关，也没有测量真实玩家完成率。

## 主要判断

八张环境图已建立场景差异，但当前主要循环仍为“寻找标记—打开文字题—获得数字—前往下一标记”。可操作的道具、环境因果和自主探索还不足。下一轮应让玩家能观察、试验、改变场景，并看到变化如何帮助自己和其他角色。

优先修复界面可用性、危险公平性与结局记录，再用春日花谷验证一套更完整的互动；通过后逐关复用。

### 确定性核对结果

- 共 8 关、32 道主谜题；每关均有 sequence、choice、pattern、number 各一道，全部为线性依赖链。
- 7 道选项已按正确顺序排列的谜题：alarm、mill、lily-path、tide-route、lightning、signal-order、flower-bridge。drain-order 不在此列。
- 模拟现有印章收集逻辑后得到“好生活明天再见”，长度 7；`stamps.length === LEVELS.length` 为 false。这是数据逻辑复现，不是声称已经实机重玩到结局。
- 在带电积水区域中心偏移 `(75, 33)` 的点，现有矩形致死判定成立，而绘制的旋转椭圆判定不成立。

## 操作与反馈还可以怎样改

### 移动和镜头

当前起步确有速度缓动，但终点到达后坐标立即停止，速度变量继续衰减；步行动作会短暂保持，而不是提前减速到达。脚步事件发生在累计路程 16、46、76……，身体上抬峰值约在 15、45、75……，声音与视觉接地的相位仍需要对齐。

建议按剩余路程提前收步，取消或危险停步保持即时响应；帧表使用统一头部位置、脚底锚点和面向。镜头跟随改为基于 delta 的响应，避免不同刷新率下手感改变。下一批动作优先补 passing 中间帧与左右独立侧身，再考虑装饰性表情。

自动路线目前只检查下一路径节点是否进入正在生效的危险。简化后的长线段可能穿过刚激活的危险而终点节点仍在外面。应检查实际行进线段和临近危险，并保留目的地，让玩家明确选择等待或改道。角色已经处于危险区时优先允许撤离。

### 线索、提示与关底

引导应明确目的和下一种可尝试的行为，例如“让溪水重新流进花田”，再由水声、断流和园丁的朝向吸引注意。金色光边继续用于确认互动，精确位置指引可按需展开；三级提示分别回答注意什么、关系是什么、具体怎么做。

多数题目在同一个弹窗中同时给出全部证据和操作，缺少观察与整合的过程。建议一个主要线索来自环境，一个来自人物或物件；日志自动收集，不要求玩家背长文字。

关底口令应来自玩家见过的现象，例如三枚转动的木销、一个缺口、四朵开放的花和两组脚印。避免“解出 8，奖励又刻着无关联的 9”这类二次任意编号。口令弹层内应可直接翻开已发现的记忆卡，保留当前输入；现有抽屉层级低于口令弹层，来回关闭查阅会打断思路。

### 支线、角色和成就

每关先制作一个能被记住的角色互动。小猫被救后从纸箱里探头并跟到屋檐，园丁收到工具后恢复劳作，同行者会在终点留一句回应。对话保持一两句，让行为承担大部分叙事。

工具由情境自动推荐，也允许点击快捷栏选择后再点目标；提供“正在用什么”“可用在哪里”“为什么不能用”的反馈。第一批做水壶、绳子、手电等少量可跨场景复用工具，控制在现有快捷栏容量内，不引入复杂合成树。

把观察收藏、照片和成就集中放进日志。优先奖励不同的玩法：找到回环捷径、依据预兆成功避险、帮助角色、观察罕见自然现象。使用提示不扣情感奖励，死亡次数不作为羞辱标签，支线不要求全部完成才能看正式结局。

### 危险与安静时刻

教学区先完整展示征兆和安全反应，后续区域再组合应用；错误解谜允许安全试验。危险的时机应让玩家能理解原因，不按死亡次数硬凑内容。

重来保留已发现线索和世界恢复状态；用明确的休息点作为检查点，重试从安全位置与明确的危险阶段开始，减少无新信息的赶路。当前 restartAfterDeath 不重置 elapsedSeconds，和总纲中“重置危险周期”的文字需要统一。

安静区域应允许主动停留：坐在长椅、听瀑布、看蝴蝶、小猫靠近。随后以环境或角色的一点变化回应停留，让“珍惜今天”通过经历传达。照片记录玩家完成的小事，并在八日最后按顺序翻阅。

## 春日花谷样板关：建议方案

以下为待实施提案，目标首通仍沿用总纲的 12—18 分钟，完整探索时长待真人测试。

| 段落 | 玩家做什么 | 反馈与学习 |
| --- | --- | --- |
| 到达 | 看见干涸支渠、闭合花朵和停住的水磨；园丁提示“先看看水到哪里断了”。 | 获得可理解的目的，水声与可见水路提供自然方向。 |
| 学会操作 | 在安全水磨设施上实际关闸、用工具清叶、扶正木销、开闸。闸未关时机械护罩阻止清理，并给出原因。 | 工具与机关有清楚前置条件；局部完成保留，水流与水轮即时改变。 |
| 自主探索 | 恢复水路后开放两条短支路：野餐布角拼合，以及蜂群与花圃观察，可先做任意一条。 | 两条线各有独立证据与小回报；回程开启一条捷径，降低往返负担。 |
| 组合推理 | 玩家结合已记录的花色、针脚或脚印方向，在场景中选择正确部件和行进方向。 | 规则都曾展示，难度来自组合；错误保留已发现证据并指出未满足的条件。 |
| 生活支线 | 找回茶杯后邀请园丁在屋檐下喝茶；可顺路帮助小蜂。 | 角色有动作与回应，照片里会出现相应细节；不会阻断主线。 |
| 收束 | 在小屋按门上符号顺序对照记忆卡输入口令，翻看这一天的照片。 | 数字与亲历事件对应；结局既确认解谜，也回应玩家做过的小事。 |

水磨是教学谜题，复杂度来自之后跨地点的证据组合。不能仅把现有正确顺序改为拖拽，然后仍由同一段文字给出全部答案。

## 实施顺序与验收

1. 修复体验基础：窄屏/全屏入口、危险图形一致性、印章与旧存档恢复、答案呈现顺序、口令查阅。这里只修已确认问题，不改变八关谜底。
2. 春日花谷制作样板：精确导航区域和前景遮挡、一条有状态变化的水路、两个独立探索分支、实际工具使用、一个角色支线、一张会变化的照片。
3. 用新玩家验证样板，再按上表推广八关，最后扩展声音变体与成就。

验收目标（尚未实测达成）：

- 390px 竖屏、横屏以及桌面下，主目标、角色和移动区域可辨，能从当前页面进入全屏或合适的展开视图。
- 危险画面与判定共用几何；不存在“预警区外致死”的未标记角落。检查危险中途激活、对话后恢复和检查点重试。
- 八关全部完成后正确形成“好好生活，明天再见”；旧存档也按关卡恢复两枚“好”。
- 每个主谜题有至少一项持久可见的世界变化，至少一个工具在样板关有两个合理用途。
- 样板关有两个可交换探索顺序的分支、一条可解锁回环、一处可选安静停留点。
- 先找 5—8 名未看攻略的新玩家：以至少 4/5 或 6/8 能在 60 秒内说出当前目的、在不使用 H3 的情况下完成教学谜题作为首轮门槛；小样本用于发现问题，不宣称统计结论。
- 记录停滞位置、错误选择、H1/H2/H3 使用和死亡前的输入。访谈追问“你做了什么让环境变化”“哪件小事最记得”，不要只问好不好玩。

## 维护说明

当前 main.ts 运行的是 CampaignGame，旧 src/game/Game.ts 中的自然发现、部分互动和成就并不等于已经接入八关版。总纲、早期路线图与新实现还存在危险导航、危险周期和动作完成度的描述差异。后续实施时应以实际接入状态更新来源文档，避免把旧单关功能当作八关已具备的能力。
