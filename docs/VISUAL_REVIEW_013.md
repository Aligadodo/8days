# 0.13 独立视觉契约复核

本报告与关卡作者分工独立，仅记录检查证据与可证实的结果。检查范围为 8 关、56 个原目标和 7 个机关。标准见 `VISUAL_ACCEPTANCE_013.md`，逐对象处理见两份关卡审计报告。静态契约通过不等于美术通过。

## 旧验收为何没有发现截图问题

- `campaign.test.mjs` 使用空 Canvas context，验证走到站位后能否触发、保存及通关，没有实际执行材质/透视绘制。因此 40 项逻辑测试通过完全可能与“柜子像贴纸”同时发生。
- `navigation.test.mjs` 验证 authored approach 在导航模型内可达，无法判断该模型是否错误地把原画墙顶当成地坪。独立障碍负样本有价值，但没有覆盖所有家具和支持面。
- 原有“全部物件中心距大于 34”只能拦住极近中心，不能证明尺寸不同的轮廓不重叠，也不能证明两个相邻的原生按钮不应存在。视觉间距不能用固定中心距离替代。
- 原实现所有大物件统一脚底阴影、机关矩形命中、柜门平涂绘制。即使路径和机关状态正确，桌上物、墙挂物仍会有假落地、空区域仍吃点击、状态变化仍像 UI 动画。

## 已见图像与高风险点

独立读取了全部 8 张生产地图、`world-props` / `utility-props` 原始图集，以及办公室两张生成开门原图；用户截图也明确展示办公室旧柜子/拉杆风格与安装面不合格。尚未将所有关卡各阶段的运行画面逐帧验收。

| 场景 | 独立观察 | 要求 |
| --- | --- | --- |
| 办公室隔断 | 旧 `(973,341)` 邻近位置是隔墙立面/墙顶，不能当柜子落脚地板 | 移除旧平面柜子；原画检修门、壁柱开关优先绑定；站位必须同侧 |
| 办公室最右入口 | 原门框在绿色疏散道右上端，旧机关中心偏到走道前方 | 门关闭态、门槛、开态、通路使用同一门框；坐标必须叠图确认 |
| 办公室工位 | 原画已有显示器、配电柜、墙上图纸、打印机 | 不再重叠一个独立巨大屏幕/地图讲台；桌上/墙挂对象不使用地面椭圆阴影 |
| 矿洞 | 原画已有矿车、晶簇、花桥、晨光台阶 | 背景绑定优于再放微缩矿车、晶簇或路牌图标 |
| 矿洞可破墙支路 | 原壁龛通路向悬崖/晶簇方向上爬，程序铺石不能证明那里存在可行走地坪 | 重定位到轨道旁可解释的浅壁龛，闭合、破开、手记出现及碰撞同步 |
| 山间营地 | 木桌原画是提环煤油灯，不能通过 support 写“壶与灯具”把它绑定成保温壶 | 保留真实身份；小保温壶可另置于桌面，不以文字偷换原画物体 |
| 救援哨 | 图集中是木底座挂架加哨子，不是独立地面哨 | 缩放、安装方式和提示必须描述完整挂架，不能把组合物缩成贴地玩具 |
| 雪站终点 | 新终点绑定站房门，而主线涉及车厢编组 | 到站房验证登车信息与立即进入车厢是不同动作，出口反馈须与画面身份一致 |

以上发现已分别发给关卡作者及共享渲染负责人，坐标建议均标为原图估测，而非已验收坐标。办公室消防门的第一次坐标粗估在看到生成图后发现可能包含护栏，已明确撤回其最终标定适用性；第一张生成图也把消防门画到了下方走道，应使用重新生成的正确墙门开态再叠图标定。此例说明独立审查也必须反复核对图像，不能把评审者猜测变成坐标权威。

## 新增自动化覆盖

`tests/visual-contract.test.mjs` 增加以下可重复检查：

- 锁定本轮 56 + 7 对象清单；每个原目标显式登记 mount、具体 support、绘制层和可选深度，不遗漏出口。
- 绑定原画的 polygon 非退化且处于画布范围；站位/锚点有限；世界数据传入运行实体时不能丢失 baked、尺寸或 atlas/frame 覆盖。
- 机关必须配置原画形体或闭合位图，不能依靠旧代码兜底成柜、杆、墙、篮子；门与破墙必须提供打开后的图像状态。
- 引用的 PNG 资产必须存在于项目 public 内；原生图片尺寸、裁切范围、世界绘制尺寸与偏移合法。
- 墙挂/桌上/悬挂/门不画独立地面椭圆；地面纹样不压住人物；实体深度的共享规则有直接单元测试。
- 人工 2×2 alpha 样本验证位图绘制与命中使用同一锚点/偏移，透明部分不可点，未加载素材不可退回隐形矩形，悬停只添加薄轮廓。
- 调用真实机关绘制入口，缺失资产时不产生任何平涂家具兜底形体。
- 调用真实原画绑定绘制入口，断言先 clip 再重绘物件本体，之后才叠完成态/悬停；只有深度排序但没有重绘本体时测试会失败。
- 原画绑定的门/机关使用同样的本体重绘契约；完成后不能保留闭合形态光边或吞掉门洞点击。
- 直接验证旧 SpriteAtlas 空帧时不再返回矩形命中；新增通路必须有真实 raster 石材/木板，缺图时不能静默回退成连续灰色道路。

这些测试不检查“support 描述所说的墙是否真的在图中”“光源、材质、透视是否匹配”“生成 PNG 是否内含错误伪透明棋盘格”。它们属于必须看图的人工判断，不能通过填写字段绕过。

## 合并前实机清单

1. 办公室：拉柄首次出现、未通电、通电、操作中、开门后各看一次；人走到门前，门框/人物/墙的遮挡不反转；已开的门洞不抢点击。
2. 矿洞：锤子拿取、裂墙敲击中、破开、收藏物出现与拿取、藤门打开。小锤拿取后不能留下旧工具形体的隐形热区。
3. 每关抽查一个墙/桌/水面高风险对象和一个支线生物，悬停轮廓必须跟实物，不是四方提示框；完成后仍检查形体、站位与热区。
4. 逐关确认没有新物件遮住道路、提示指向与原画对象名称不符、上下层遥控交互。
5. 普通窗口和全屏各看一次用户截图的问题区域；缩放时轮廓不要变成巨大边框。
6. 所有实机测试使用独立测试 origin；不清除或重置用户当前游戏存档。

## 本次独立复核促成的修复

1. 共享绘制新增原画物体按支撑深度 clip 重绘，修正“只排光边、不排实体”的伪遮挡；旧图集空帧不可点击。
2. 原画绑定不等于任意改名：保温壶/煤油灯、独立哨/整座挂架、封砌石龛/天然岩壁、站房门/列车车厢分别对照真实身份修订。
3. 办公室开门素材必须对准同一真实门框，生成结果选错门的位置被独立复核指出后返工，而不是因 PNG 文件合法就接受。
4. 审阅台增加“开墙未取收藏”状态，避免“全开”顺便领取收藏导致关键可见状态永远被跳过。

后续若更改资产、坐标、裁切或站位，应重跑契约与逻辑回归，并重看对应画面；不得仅修改 support 文本来消除视觉不合格。
