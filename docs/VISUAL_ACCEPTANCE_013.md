# 0.13 世界物件验收标准

适用：八关全部 56 个原有交互对象、7 个新增世界实体、补路和危险源表现。自动化可达性不是视觉合格证明。本轮用户截图作为不合格样本：漂浮的正视书柜、平涂拉杆、墙顶上的机关，无论路径是否通过都必须返工。

## 七项独立检查

| 项目 | 合格条件 | 必须返工的例子 |
| --- | --- | --- |
| 风格与透视 | 像素密度、视角与所在地图一致；可看出上面/侧面，不能用 UI 图标充当场景物体 | 正视矩形书柜放进斜俯视办公室；纯色矢量块 |
| 比例与材质 | 对照主角、门和桌子判断真实尺寸；有同场景的明暗、纹理、接触阴影 | 电话比门大；工具箱像人物一样高；矿洞里出现明亮办公室配色 |
| 安装或落地 | 每件物品记录 mount + support：地面、墙、桌面、悬挂、门或人物；该支撑在图中真实存在 | 拉杆悬在栏杆外；阀门浮在瀑布壁上；书柜底部没有地面 |
| 遮挡与命中 | 按支撑面深度排序；桌上物不被人物反向覆盖；只悬停实物形体描边 | 人在墙后却盖住墙；空门洞仍吃点击；矩形热区覆盖其他物体 |
| 操作站位 | approach 在真正可走地面且处于能操作的一侧；不能把相距很远的目标绑成遥控按钮 | 在下面楼层操作上层物件；隔桌/隔墙伸手超过合理距离 |
| 状态变化 | 关闭、操作中、完成都检查；状态变化与碰撞同步；保持材质/透视 | 柜子突然变黑矩形；破墙后生成亮色木板贴纸；已开门仍有隐形墙 |
| 玩法与可达性 | 主线/支线/机关按顺序可达；取消不毁状态；旧进度可迁移；危险预警与避让仍有效 | 漂亮但无路到达；移物堵住窄路；收藏抢占主线口令 |

## 实施约束

- 优先复用背景中真实存在的门、桌上物、工具、栏杆、灯和控制面板，配置精确 polygon 与站位，避免再叠一份“解释性图标”。
- 必须新增的场景物使用与地图一致的 raster 资产。使用 imagegen 时阅读技能，用地图作为参考；保留提示词、生成原图、裁切/锚点规格和工作区文件。禁止把程序化大色块作为“修复后的精美素材”交付。
- 粒子、水纹、细光边和小灯等效果可继续代码绘制；承载物件形体的柜、门、墙、箱、工具不能依靠粗糙几何图标冒充。
- 每关逐项列出所有对象的处理：保留并验证 / 改绑背景 / 缩放或移位 / 重做素材。不能只检查截图里的两件。
- 源数据拆成 `src/campaign/worlds/day01.ts` … `day08.ts`，并行人员只写各自关卡文件和自己的报告/素材目录。共享渲染、schema、版本和存档由主会话维护。
- 各组报告明确区分：图像审阅、自动化验证、实机验证、仍待核实。未见实机状态不得标“全部通过”。

## 合并验收

1. 静态合同：全部对象有支撑说明；禁止旧 flat mechanism 形体兜底；生成资产存在；明确贴地/墙挂/桌面排序。
2. 逻辑回归：主线、全部支线和机关链、碰撞负样本、动态状态和存档迁移。
3. 实机抽查：用户指出的办公室同位置、矿洞裂墙前后，以及其他关卡的高风险物件。必要时截图重验而非只读坐标。
4. 未完成项如实记录，不能用测试数量替代材质、布局与认知判断。

## 每轮执行记录

- 对象清单：按关卡与稳定 ID 逐件登记，记录真实支撑、素材来源、站位、碰撞和前置条件；新增对象必须追加，不能只看主线。
- 状态清单：初见、悬停、走近、动作中、取消、完成、离开再返回、读档。门/墙另外核对开闭两侧通行；收藏另外核对“已露出但未拾取”，不能被“全开”模式跳过。
- 体验清单：正常窗口与大画面、鼠标/键盘、窄路转角、人物经过前后、迷雾与小地图、提示语和音效字幕。危害抽查预警可见、可撤离、暂停冻结、命中/躲开、重来不重复发奖。
- 证据清单：每条结论注明代码/自动化/实际合成图/实际操作中的哪一种。作者与独立复核分别署明范围；独立者可驳回，修复后再看对应状态，而非沿用修复前的“通过”。
- 优先级：穿墙、主线死锁、进度丢失为 P0；支撑错误、明显异风格、错位热区、拼片接缝为 P1；过渡动画和细节丰富度为 P2。P0/P1 不能以测试数量冲抵；未处理的 P2 必须写进交付边界。
- 隔离要求：专用测试 origin，不读取或重置玩家正在玩的源；各修复组仅改约定文件，主会话统一合并共享渲染与存档，最后关闭测试标签和临时服务。

本轮实测记录见 `QA_013.md`；标准本身不表示上述所有状态已经全部执行。
