# 决策记录

## 2026-09-06

### D-001：独立项目

游戏使用 `D:\projects\OneMoreDayGame` 独立维护，不与 EasyFileManager 共用代码、依赖或版本历史。

### D-002：首个原型关卡

先实现春日花谷。它的情绪明亮、危险类型少，适合验证移动、探索、道具、线索和死亡重来，而不会被复杂灾害系统干扰。

### D-003：技术形式

首个版本采用 TypeScript、HTML Canvas 和 Vite。目标是快速建立可玩的网页原型；关卡数据与引擎逻辑保持分离，后续可以继续扩关或迁移到专业游戏引擎。

### D-004：持久化

原型使用浏览器本地存储保存死亡次数、已发现线索、辅助设置和通关状态。关卡道具在死亡后重置。

### D-005：危险公平性

不加入无法预判的随机死亡。每个致命危险必须同时具备预警、反应时间、安全方案和死亡后的明确解释。

### D-006：鼠标优先的统一操作

桌面端使用左键同时承担点地移动与场景交互：点击目标后角色自动寻路到有效距离并调查，按住左键持续跟随，右键取消。键盘保留为备用输入。该方案减少模式切换，也更符合当前网页原型的主要使用场景。

### D-007：寻路提供有限的危险辅助

A* 处理静态导航网络，并避开当前正在生效的致命区域；预警区域只增加路径代价。危险在移动途中生效时自动暂停而不是替玩家完成等待判断，从而兼顾鼠标操作可信度与观察玩法。

### D-008：高清内部渲染与近景镜头

逻辑视野改为 `800×450`，Canvas 使用固定 2 倍内部缓冲输出。出生区重新排列为“主角—工具箱—磨坊—石桥”，确保首个目标与大地标同时进入镜头。

### D-009：四色交互语义

所有未完成可交互物使用统一的四角像素光边，但按主线金、工具蓝、小事绿、观察粉区分意图。普通装饰无光边，危险只使用红色预警。完成后主动光边熄灭，物件仍支持重复查看。

### D-010：丰富度来自横向活动

原型不增加战斗、经验等级和货币。内容扩展使用一条主线、三件今日小事、五个自然发现和九项非数值成就，让同一张地图同时支持推进、观察、停留和环境修复。

### D-011：日志承担所有长期目标

任务、口令、自然发现和成就都进入现有日志标签并随本地存档保留。不新增任务中心、成就大厅或收藏页面，以保持常驻界面极简。

## 2026-09-07

### D-012：谜题是一份可验证的契约

所有主线谜题必须在世界内提供完整必要信息，并写清意图、动词、规则、证据、反馈和恢复。难度来自规则组合，不来自像素搜寻、现实冷知识或不可解释的随机试错。

### D-013：新规则先安全教学

危险使用的环境信号必须先在无致命惩罚区域展示和教学，再进入独立测试与组合。春日花谷的丝带、花朵和风声先在风向杆安全区形成规律，随后才用于阵风通行。

### D-014：音频使用语义事件层

原型以 Web Audio API 建立 UI、移动、交互、谜题、危险和环境的语义事件，不让关卡逻辑直接依赖具体文件名。音乐、效果和环境可独立调节，事件名与总线结构可在未来迁移引擎时保留。

### D-015：关键反馈必须跨感官表达

重要谜题与危险信息至少同时通过视觉、声音、运动或文字中的两种渠道表达。提供重要声音字幕与单声道替代方向提示，确保静音、听力差异和色觉差异条件下仍可完成主线。

### D-016：参考项目只用于方法研究

《星露谷物语》《Celeste》等作品只用于研究活动密度、音乐节奏、事件组织和反馈层级。项目不得复制或改编其音频、地图、角色或其他受保护资产；所有发布素材必须保留来源与许可记录。

### D-017：0.4 使用程序化占位音验证语义

在正式采购、委托或制作声音素材前，先用 Web Audio 合成点击、脚步、谜题、危险和完成提示，验证事件时机、总线、冷却、空间声像与字幕。程序化声音是功能占位，不作为最终音色方向，也不阻塞后续替换素材。

### D-018：八关使用同一数据驱动战役引擎

0.8 不复制八套关卡代码。关卡数据统一描述主题、路线、四个谜题、支线、危险、地标、口令与结尾；引擎负责寻路、交互、危险周期、持久化和绘制。启动时校验内容预算与口令推导，防止配置与结算脱节。

### D-019：口令是二次推导，不是四个数字收集点

每个谜题完成后记录“符号＝数字”，终点只给出符号的新顺序。玩家必须回看日志重组口令。这样既保留四位口令的统一仪式，又让谜底来自观察与推理，而不是地图里直接抄数。

### D-020：引导采用一条常驻目标和可选提示阶梯

不新增任务中心。地图上只强调当前可推进主线，常驻任务卡说明当前动作与原因，离屏箭头负责方向；H1—H3 提示由玩家主动展开并记录使用量。未请求提示的玩家仍可依靠 H0 现场证据独立解题。

### D-021：全屏与清晰度优先保持比例

普通页面使用严格 16:9 容器和 `960×540` 逻辑画布的 2 倍缓冲，避免 max-height 导致的非等比拉伸。桌面全屏由浏览器 Fullscreen API 驱动；Canvas 禁用平滑并使用整数坐标，保证像素边缘清楚。

### D-022：场景绘制与交互层分离

八张环境图只承载地貌、建筑、植被、光照和氛围，不烘焙角色、任务标记、文字或 HUD。引擎单独绘制交互光边、危险预警、角色和天气，因此谜题状态变化、无障碍提示与后续地图替换不会污染基础画面。

### D-023：正式绘制使用人工标注导航网络

每关数据维护一条可重复经过枢纽的隐藏路线网络。寻路网格必须落在网络 118 世界像素范围内，所有出生点、谜题、支线和出口在启动时接受连通性校验。这是当前整幅环境绘制方案下防止角色穿墙、涉水的过渡导航形式；后续拆层后升级为多边形导航网格。
