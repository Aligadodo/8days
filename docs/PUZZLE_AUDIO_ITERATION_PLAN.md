# 解谜关卡与音频迭代方案

> 状态：0.4 设计基线；适用范围：春日花谷重构，以及后续所有单关卡。
>
> 核心目标：让玩家因为“理解了环境规律”而通关，而不是因为找齐四个直接写出的数字。

## 1. 研究结论与项目边界

本方案学习经典游戏的设计方法，不复制其角色、地图、谜题、音乐或音效资产。

- 《星露谷物语》的官方介绍把耕种、采集、钓鱼、采矿、社交和修复社区放在同一个世界中。可迁移的不是这些具体职业，而是“一张地图同时支持主线、日常动作、观察、收集和环境变化”的活动密度。[Stardew Valley — About](https://www.stardewvalley.net/about/)
- ConcernedApe 在开发日志中说明，每首音乐服务于当前场景和季节气质，而且户外季节曲目不会持续循环，歌曲之间由季节环境声填充。可迁移原则是“音乐负责情绪段落，环境声负责空间连续性”。[Stardew Valley — Dev Update #16](https://www.stardewvalley.net/category/media/page/2/)
- GDC 的谜题写作总结把谜题定义为设计者与玩家之间的契约：设计者必须给出全部必要信息，同时让谜题与世界、叙事共同推进。可迁移原则是“不靠隐藏关键像素、不靠猜设计者心思”。[GDC Vault — Puzzle Writing: Best Practices](https://www.gdcvault.com/play/1013851/Puzzle-Writing-Best)
- GDC 的教学讨论指出，过易会无聊、过难会挫败。对本项目而言，难度应该由规则的组合数量逐步上升，而不是通过延长跑图或减少提示制造。[GDC Vault — Teaching Puzzle Design](https://www.gdcvault.com/play/1025845/Teaching-Puzzle)
- FMOD 公布的《Celeste》教学项目适合研究事件、参数和混音结构，但其工程与源音频具有明确的教育用途许可边界。本项目只学习组织方式，所有可发布素材必须原创、委托制作或使用兼容授权。[FMOD — Celeste Getting Started Guide](https://www.fmod.com/docs/2.03/studio/appendix-a-celeste.html)
- Microsoft 的游戏无障碍指南要求重要信息不要只通过单一感官表达；可交互物可同时使用视觉光边与空间音频提示，重要非语言声音应有文字等价信息，音乐、效果和语音等类别应可独立调节。[XAG 103](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103)、[XAG 104](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/104)、[XAG 105](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/105)

## 2. 0.3 原型诊断

| 维度 | 现状 | 0.4 要解决的问题 |
| --- | --- | --- |
| 地图可读性 | 五个视觉区域、地标和鼠标寻路已经成立 | 让谜题信息也依附于地标和路线，而不是只存在于弹窗文字中 |
| 交互识别 | 四类光边能区分目标类型 | 交互前后要有动作、声音和世界状态变化，减少“一点就收走” |
| 主线谜题 | 四处找到 `3-1-4-2`，最终抄入口令 | 增加规则教学、观察验证、跨物件关系和最终重组 |
| 今日小事 | 多数是一次点击完成 | 至少一项观察、一项环境修复、一项技巧挑战 |
| 危险 | 有预警、死亡解释与重试 | 在安全区先教学同一种信号，再在危险区考核 |
| 反馈 | 以文字框、光边和少量动画为主 | 建立点击、行走、交互、谜题、危险、完成的统一声音语言 |
| 辅助 | 重复死亡会加强危险提示 | 谜题也需要按停滞时间和错误次数递进的提示阶梯 |

最重要的判断是：当前内容已经像“可探索的游戏关卡”，但还没有形成完整的“谜题语言”。0.4 不应先继续扩大地图，而应把花谷现有物件改造成一条可教学、可推理、可复用的谜题链。

## 3. 专业解谜框架

### 3.1 每个谜题必须回答六个问题

1. **意图**：这个谜题在情绪、故事或生存主题上表达什么？
2. **动词**：玩家实际执行什么动作，例如观察、摆放、连接、等待、选择或避让？
3. **规则**：玩家需要理解的一句话规律是什么？
4. **证据**：游戏在哪里完整提供了推理所需的信息？
5. **反馈**：尝试、局部正确、错误和完成分别怎样被看见与听见？
6. **恢复**：错误能否立即重试，是否会丢失不可恢复的信息？

若其中任何一项无法写清，谜题不能进入制作。

### 3.2 单关教学曲线

每关最多引入两个新规则词，并按以下顺序组织：

```text
展示 Expose → 教会 Teach → 独立测试 Test → 变化 Twist → 组合 Combine → 回忆 Remind
```

- **展示**：在安全、无惩罚的环境中播放信号。
- **教会**：玩家做一次明确动作，立即看到因果关系。
- **独立测试**：去掉文字指令，只保留已经学过的信号。
- **变化**：空间、时序或目标发生一个变化，不同时改变多个维度。
- **组合**：把本关两个已学规则放进同一场景。
- **回忆**：终点以简短方式复用规则，让玩家确认自己真的理解。

春日花谷作为第一关只做到“展示—教会—独立测试—一次组合”；彩虹瀑布再引入更复杂的水流与层级路线组合。

### 3.3 谜题原子与状态

每个谜题原子统一使用下列状态，方便关卡数据化与保存：

```text
unseen → noticed → attempted → partial → solved
                    └──────────→ resettable
```

- `noticed`：玩家已接近、观察或读到规则证据。
- `attempted`：做过至少一次有效操作。
- `partial`：获得明确的局部正确反馈，但不提前播放完成庆祝。
- `solved`：世界发生可持续的视觉与声音变化。
- `resettable`：错误不会锁死路线，可在原地一键恢复或自动复位。

### 3.4 难度来自哪里

可使用的难度来源：

- 需要关联两个相隔不远的环境证据；
- 在安全地学会信号，再在轻度压力中应用；
- 同一工具在两个物件上产生不同但一致的结果；
- 先得到“图案—数字”关系，最后再根据门上的图案顺序重组；
- 可选谜题把主线规则变形一次，奖励发现或成就。

禁止使用的伪难度：

- 关键物件只有一两个像素且无任何提示；
- 依赖现实冷知识、作者私有联想或随机试错；
- 多个按钮没有局部反馈，只在最后告知全错；
- 失败后必须重复长距离跑图或重新播放不可跳过文本；
- 用更响、更突然的声音代替公平预警。

### 3.5 可复用谜题类型库

后续关卡优先组合已经验证的谜题类型，不为每关重新发明一套操作界面。

| 类型 | 核心动词 | 可复用组件 | 合适的变化方式 |
| --- | --- | --- | --- |
| 环境修复 | 清理、连接、装回、开启 | 工具门、修复点、状态动画 | 修复后改变通路、声音或另一个对象 |
| 缺口补全 | 比较、放置、配对 | 可选槽位、手持道具、轮廓痕迹 | 缺形状、缺数量、缺方向 |
| 顺序规律 | 观察、重放、排列 | 四段状态、局部确认、重置 | 空间顺序、时间顺序、因果顺序 |
| 空间关系 | 对照、定位、绕行 | 地标、地图、影子、流向 | 镜像、高低层、遮挡前后 |
| 时机窗口 | 等待、通过、停下 | 世界仪表、周期状态、安全区 | 周期长度、移动路径、两个信号组合 |
| 资源回路 | 获取、使用、补充 | 容器、补给点、多个用途 | 先后顺序、远近成本、可恢复误用 |
| 逻辑重组 | 关联、排除、输入 | 图案—数字日志、门锁、关系句 | 位置关系、先后关系、唯一排除 |
| 路线规划 | 侦察、选择、折返 | 多出口房间、风险标记、可开捷径 | 水位、能见度、临时封路 |

第一关不使用超过两步的逻辑排除；最终关可以组合三种已学类型，但不得同时引入新的操作语法。

### 3.6 单关内容预算

- 主线谜题：3–5 个，其中至少一个教学、一个独立测试、一个组合。
- 主线谜题面板：最多一个；其余解题发生在场景内，避免连续弹窗。
- 新规则词：最多两个；旧规则可复用一至两个。
- 可选谜题：1–3 个，只变形已学规则，不藏主线必要信息。
- 主线关键物件：任一时刻最多两个未解决目标同时竞争注意力。
- 纯阅读线索：最多一条；其他证据由空间、状态、动作或声音共同承载。
- 同一谜题的必要证据跨度：第一关不超过一个相邻视觉区域；后续关再逐步扩大。

### 3.7 八关差异化方向

四位口令是统一的结算结构，但每关推导数字的方式必须不同，避免八次“找四张纸”。

| 关卡 | 主谜题语法 | 口令信息怎样产生 | 复用与升级 |
| --- | --- | --- | --- |
| 暴雨通勤 | 路线规划 + 环境修复 | 公交信息、积水刻度和安全路标相互对照 | 花谷的世界仪表升级为变化水位 |
| 深夜加班 | 空间关系 + 逻辑重组 | 配电隔离状态与疏散图房间号建立映射 | 第一次加入室内上下层与烟雾阻断 |
| 春日花谷 | 修复 + 缺口补全 + 时机窗口 | 四个生活动作建立图案—数字关系 | 安全教学基本交互和危险节奏 |
| 彩虹瀑布 | 资源回路 + 顺序规律 | 水闸次序改变各层水位，正确状态露出刻度 | 把花谷单次浇水升级为可逆水路系统 |
| 秋日河湾 | 路线规划 + 时间顺序 | 潮汐记录与地标出现顺序共同确定数字 | 把周期危险升级为整张地图路线选择 |
| 山谷骤雨 | 空间关系 + 生存判断 | 高程、雷声间隔和避难标志排除错误路线 | 玩家先做安全决策，再获得口令证据 |
| 暴雪末班车 | 顺序规律 + 声音定位 | 信号灯、站台广播字幕和车厢位置互证 | 声音提供方向但始终有视觉等价提示 |
| 发光地下河 | 旧规则组合 + 回忆 | 前七关照片中的视觉语法在地下环境重新出现 | 不引入新规则，考核跨关记忆与迁移 |

每关正式制作前仍需使用策划卡验证唯一性和公平性；上表是设计边界，不是锁死答案的脚本。

## 4. 春日花谷 0.4 谜题链

口令继续使用 `3142`，以兼容现有存档和结算；获取方式从“直接抄数字”升级为“完成四个生活动作，建立图案与数字的关系”。门上只显示四个图案顺序，不直接列出数字顺序。

### 4.1 主线拓扑

```text
出生区
 ├─ P1 疏通磨坊水槽 ─────────────── 得到「水轮 = 3」
 └─ P2 补全野餐座位 ─────────────── 得到「茶杯 = 1」
                       ↓
             P3 给风向杆系上丝带
                       ↓ 安全学会“垂落才是静风”
             H1 穿过周期阵风区
                       ↓
             P4 浇花并观察四声风铃 ─ 得到「花信 = 4」
                       ↓ 蜜蜂飞回蜂箱，露出黄铜钥匙
             H2 根据裂响与阴影避开枯枝
                       ↓
             P5 门前辨认两组归家脚印 ─ 得到「屋檐 = 2」
                       ↓
             门上图案：水轮 → 茶杯 → 花信 → 屋檐
                       ↓
                     3142
```

P1 与 P2 可以交换顺序，避免开场像一条走廊；P3 之后逐步收束，使教学和节奏可控。

### 4.2 谜题卡

#### P1 疏通磨坊水槽：建立“动作会改变世界”

- 意图：普通劳动也值得被记住。
- 动词：拾取小铲，清理叶泥。
- 规则：水路畅通，水轮才会转动。
- 证据：停转的水轮、溢出的浅水、叶泥堆和磨坊墙上的旧维修画。
- 反馈：铲土三下，水声由散乱变连续，轮轴上的木销敲钟三次；同时出现三个金色水波。
- 结果：日志记录“水轮 = 3”，磨坊环境声永久变为运行态。
- 恢复：没有失败态；若玩家没有小铲，点击泥堆提示“这不是用手能扒开的一团湿叶”。

#### P2 补全野餐座位：建立“观察缺口”

- 意图：有人为迟到的人留了位置。
- 动词：观察四个位置，把篮中的备用杯放到缺杯的位置。
- 规则：完整的一组里，缺少的部分就是目标。
- 证据：四张坐垫、三个已有杯印、一个干净圆痕和便笺“替迟到的人留一杯”。
- 反馈：放错时杯子轻轻碰桌并回到篮中；放对时桌布角翻起，露出单朵刺绣花。
- 结果：日志记录“茶杯 = 1”，获得可以系在风向杆上的红丝带。
- 恢复：错误不消耗道具，复位时间不超过 0.5 秒。

#### P3 风向杆：先教学，再让危险考核

- 意图：危险不是突然降临，世界一直在发出信号。
- 动词：把丝带系到风向杆，等待并观察一个完整周期。
- 规则：丝带横直、花朵压低、低沉风声代表强风；丝带垂落且风铃停止才是安全窗。
- 证据：安全围栏内的风向杆、同步弯曲的花簇和三段强弱不同的风声。
- 反馈：首次完整观察后，日志只记录图示规律，不自动替玩家过危险区。
- 测试：下一段窄路使用相同的丝带、花朵和音色，自动寻路仍不会规避阵风。
- 恢复：第一次在风区受击只吹回安全侧；重复忽略强风才进入死亡反馈。

#### P4 花信与蜂场：组合补给、时序和环境关系

- 意图：照料一小片花，会让别处重新热闹。
- 动词：在石泉装水、浇灌枯花、静听风铃。
- 规则：四簇花依次抬头，蜂群按相同顺序飞回；风铃为每簇花发出一声清晰音符。
- 证据：空水壶的轻声晃动、石泉蓝色光边、四簇由近到远的花和蜂箱前的空托盘。
- 反馈：每浇一簇只播放一声局部完成音；四簇全部复苏后才播放解决和弦，蜂群飞行路径指向钥匙。
- 结果：日志记录“花信 = 4”，蜂箱处出现黄铜钥匙，并完成今日小事“蜂场重新热闹”。
- 恢复：石泉可无限补给；水浇错装饰植物不消耗主线资源。

#### P5 归家脚印与门锁：温和的最终回忆

- 意图：有人回到了家，今天的旅程也有终点。
- 动词：观察门前泥印，将黄铜钥匙插入门锁，再按图案输入数字。
- 规则：两组脚印都指向屋内；门上图案给出四条已解线索的顺序。
- 证据：两双方向一致、尺寸不同的脚印；门框浮雕依次为水轮、茶杯、花信、屋檐。
- 反馈：每输入一位，对应图案亮起并播放其谜题的短记忆音；错误只熄灭当前输入，不抹除日志。
- 结果：日志记录“屋檐 = 2”，输入 `3142` 完成送种。
- 恢复：首次错误提示“数字都见过，门上的图案在提醒先后”；三次错误后日志自动高亮对应四项。

### 4.3 可选谜题与成就

- **树蛙回声**：河岸三只树蛙按远近发声，玩家依次点击对应荷叶，发现隐藏观察点。复用“声音有空间位置”的规则。
- **蜂场守护者**：主线花开后，再按蜂群落点顺序检查四个蜂箱，获得照片贴纸。复用 P4 的顺序，不引入新规则。
- **听懂风的人**：首次穿过风口且未被吹回，验证玩家是否掌握 P3，而不是奖励纯速度。
- **门前想明白**：一次输入正确口令。只奖励日志印章，不影响通关能力。

## 5. 提示与防卡死体系

提示根据“有效进展停滞时间”和“同类错误次数”递进，不按总游玩时间粗暴触发。

| 层级 | 触发建议 | 表现 | 信息量 |
| --- | --- | --- | --- |
| H0 环境循环 | 始终存在 | 动画、声音、构图、光边 | 告诉玩家哪里异常 |
| H1 注意力提示 | 45 秒无有效进展 | 目标物轻闪一次，主角一句观察 | 指向相关对象 |
| H2 关系提示 | 90 秒无进展或两次错误 | 日志将两个相关图标并列 | 暗示对象之间的关系 |
| H3 动作提示 | 三次错误或同一危险死亡两次 | 明确说出下一步动作 | 保证玩家继续前进 |

规则：

- 任何提示都不新增关键信息，只重新呈现玩家已经能观察到的证据。
- 玩家可以在设置中选择“自然、及时、直接”三档提示强度。
- 计时在背包、设置、结算和切换窗口时暂停。
- 输入错误、无效点击和失败必须说明“哪一类理解不对”，不能只播放否定声。

## 6. 音频设计语言

### 6.1 声音的五项职责

1. **确认操作**：鼠标点击、路线接受、取消和界面开合。
2. **表现材质**：草地、木桥、石路、浅水边具有不同脚步触感。
3. **解释状态**：机关未满足、局部正确、完成和复位具有不同声音。
4. **预告危险**：声音在危险生效前出现，并能传达方向或节奏。
5. **塑造空间与情绪**：环境声持续建立区域，音乐只在需要的情绪段落出现。

声音不能替代必要视觉信息，也不能为每个鼠标移动制造噪声。

### 6.2 统一语义

| 语义 | 音高与质感 | 视觉搭配 |
| --- | --- | --- |
| 可点击/路线接受 | 柔和、短促、中高频木质声 | 落点缩放、短点线路径 |
| 无法到达/条件不足 | 低音、干燥、无尾音 | 目标轻摇并显示缺少条件 |
| 获得普通物品 | 两个上行音粒 | 道具飞入快捷栏 |
| 获得生活线索 | 专属物件音 + 三音记忆动机 | 图案与数字写入日志 |
| 局部正确 | 单个稳定音，不播放庆祝 | 对应部件亮起 |
| 谜题完成 | 由该谜题局部声音组成的短和弦 | 世界状态永久改变 |
| 危险预警 | 与环境一致但更尖锐或更近 | 红色预警、阴影或材质运动 |
| 任务/成就 | 温暖但克制的四音动机 | 日志角标，不遮挡危险 |

### 6.3 事件清单：0.4 必需

| 事件 ID | 触发 | 变体/限制 | 文字或视觉等价 |
| --- | --- | --- | --- |
| `ui.click.soft` | 有效按钮按下 | 50 ms 内响应 | 按钮下压一像素 |
| `ui.drawer.open/close` | 背包抽屉 | 同类 150 ms 冷却 | 抽屉滑动 |
| `nav.route.accept` | 地面点击可达 | 连续按住时不重复播放 | 落点标记 |
| `nav.route.blocked` | 目标不可达 | 300 ms 冷却 | 路径变灰、落点轻摇 |
| `footstep.grass/wood/stone` | 对应地表行走 | 各 3–4 个变体，禁止连续同样本 | 行走动画与尘点 |
| `item.pickup.tool` | 获得工具 | 工具与线索音色不同 | 飞入快捷栏 |
| `item.pickup.clue` | 记录线索 | 叠加该谜题记忆音 | 日志图案写入 |
| `puzzle.partial` | 局部正确 | 同时最多一个实例 | 部件稳定亮起 |
| `puzzle.solve` | 谜题完成 | 高于环境声，低于危险警报 | 环境永久变化 |
| `puzzle.reset` | 错误复位 | 不做刺耳蜂鸣 | 错误部件回弹 |
| `hazard.wind.warn` | 阵风生效前约 1.2–1.6 秒 | 随风源左右声像移动 | 丝带、花朵、红色风线 |
| `hazard.branch.creak` | 枯枝坠落前约 1.0–1.4 秒 | 从树所在方向播放 | 地面阴影扩大；字幕“右侧树枝发出裂响” |
| `player.death.soft` | 死亡转场 | 避免惊吓式低频冲击 | 定格、花瓣散开、原因文字 |
| `task.complete` | 今日小事完成 | 危险警报时延后播放 | 日志角标 |
| `achievement.unlock` | 成就达成 | 与死亡、解谜完成错峰 | 小印章动画 |

### 6.4 春日花谷环境分层

```text
Master
├─ Music：春日主题、终点主题
├─ Active SFX：UI、脚步、道具、谜题、危险
├─ Ambience
│  ├─ Valley Bed：鸟、远风、草叶
│  ├─ Mill Zone：水槽、木轮、轴承
│  ├─ River Zone：近水、树蛙、桥板
│  ├─ Flower Zone：蜜蜂、花叶、风铃
│  └─ Cottage Zone：屋檐、远处铃声
└─ Voice/Caption：当前无配音，保留独立总线
```

- 区域环境声按距离交叉淡入淡出，不在边界突然切换。
- 开场春日主题播放约 60–90 秒后自然结束，由环境声接管；完成 P4 或接近山顶时再进入短音乐段落。
- 谜题需要安静聆听时，音乐缓降约 3–5 dB；危险警报出现时，非关键环境声短暂降低约 4 dB。
- 脚步最高约每秒 3 次；UI 同类声音设置冷却，避免按住鼠标时形成连珠噪声。
- 总输出保留约 3 dB 峰值余量；具体响度在拥有实际资产后通过设备试玩确定，不在纸面阶段伪定一个绝对数值。

### 6.5 无障碍与舒适度

- 设置提供主音量、音乐、效果、环境四个独立滑杆和一键静音；配音总线预留但当前隐藏。
- “重要声音字幕”默认开启，只显示与谜题、危险和剧情相关的非语言声音，并标注方向，例如“〔左侧：水轮敲了三下〕”。
- 危险和谜题信息同时使用声音、形状/运动和文字，不能只依赖颜色或音高。
- 提供立体声/单声道切换；单声道模式用屏幕边缘方向符号补充定位。
- 可关闭连续环境声、减弱高频危险声、关闭成就提示音。
- 浏览器失焦或游戏暂停时暂停音乐与计时；恢复时短淡入，避免声音突然跳回。

## 7. 技术落地建议

当前 TypeScript + Canvas 原型优先采用 Web Audio API，不在 0.4 阶段引入完整音频中间件。目标是先建立事件语义，未来迁移引擎时保留同一套事件名和混音分组。

### 7.1 模块结构

```text
src/audio/
├─ AudioManager.ts      # 解锁、总线、播放、暂停、存档
├─ audioEvents.ts       # 事件名到素材、音量、变体、冷却的映射
├─ ambienceZones.ts     # 地图区域、距离与交叉淡化参数
└─ captions.ts          # 重要声音字幕及方向格式

public/audio/
├─ ui/
├─ footsteps/
├─ interactions/
├─ puzzles/flower-valley/
├─ hazards/
├─ ambience/flower-valley/
└─ music/
```

### 7.2 实现规则

- 首次点击“开始今天”时解锁 AudioContext，避免浏览器自动播放限制。
- 游戏逻辑只派发语义事件，例如 `puzzle.solve`，不直接引用文件名。
- 每个高频事件配置 3–4 个变体、轻微音高变化和最短冷却；使用确定性随机种子，便于复现问题。
- 事件包含 `priority`、`bus`、`position`、`caption` 和 `cooldown`，危险优先级最高。
- 相同成就、任务和谜题完成在同一帧发生时排队，按“危险 → 谜题 → 任务 → 成就”播放。
- 原始制作文件保留 WAV；网页运行时输出 OGG，并提供兼容格式回退。所有素材登记来源、作者、许可证和编辑记录。
- 不复制或改编《星露谷物语》《Celeste》等参考游戏的音频文件。

## 8. 分阶段实施

### 0.4A：反馈骨架（优先）

- 建立 AudioManager、四条音量总线、用户手势解锁和设置存档。
- 接入 UI 点击、抽屉、路线接受/失败、拾取、谜题局部/完成、危险预警、死亡十类占位音。
- 增加重要声音字幕与同屏视觉反馈。
- 验收：静音时完整可玩；闭眼时能区分“有效点击、无效点击、危险将至”，但不能仅靠声音解谜。

### 0.4B：花谷谜题重构

- 先实现 P1、P3 与最终门锁，验证“环境状态变化—规则教学—回忆”的主链。
- 再实现 P2、P4、P5 与两项可选谜题。
- 线索日志改为保存 `symbol + evidence + digit`，未解决时只显示已发现证据，不提前揭晓答案。
- 验收：至少 70% 首次试玩者无需 H3 直接动作提示即可完成；口令暴力尝试率低于 10%。

### 0.4C：空间与情绪

- 制作四种地表脚步、五个环境区域和分段春日音乐。
- 加入区域交叉淡化、危险时动态压低环境声、暂停/失焦处理。
- 验收：试玩者仅凭画面与声音能分辨至少三个区域；连续游玩 15 分钟不反馈点击音或脚步音疲劳。

### 0.4D：试玩与调优

- 完成 5–10 名无说明试玩，记录谜题节点、首次注意、首次尝试、错误次数、提示层级、死亡位置和解题用时。
- 根据数据只调整一个变量：证据显著度、反馈清晰度或规则复杂度，避免同时改动后无法判断原因。
- 验收：主线首次通关 10–15 分钟，完整探索 15–20 分钟；单个教学谜题中位解题时间 30–90 秒，组合谜题 1–3 分钟。

## 9. 关卡验收门槛

- 每个主线谜题都能指出完整证据来源，且证据在解题前可访问。
- 每个新规则先在无致命惩罚区域出现，后在危险或组合场景中测试。
- 每次有效操作在 100 ms 内给出视觉或声音确认。
- 局部正确、完全正确、错误和条件不足四种反馈不能共用同一音效。
- 所有致命危险同时具备视觉预警、音频预警、反应时间、安全行为和死亡后说明。
- 静音、色觉差异和单声道条件下均可完成主线。
- 谜题错误可在 1 秒内重新尝试，不要求重复长距离移动。
- 关键音效和音乐素材均有可追溯的版权记录。
- 任务、谜题、声音和成就仍收纳于现有 HUD 与折叠菜单，不新增顶层功能页面。

具体关卡制作时使用 `docs/LEVEL_AUTHORING_TEMPLATE.md`，不要直接从散文描述进入编码。
