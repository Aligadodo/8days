# v0.15 空间、导航与墙体遮挡

## 本次实现

- 地面点击增加 `Navigation.routeNearestReachable(start, wanted, blocked?)`。先保留无障碍直达；不可达时寻找玩家所在连通地面的最近安全边缘，不再只找点击点周围 100 像素的某个地块。候选以 8 像素栅格搜索，再沿点击方向做连续脚印边界细化；这是游戏导航精度，不宣称数学上对任意多边形求得全局解析最近点。
- 物品、机关与门的操作继续使用 `route(start, approach, blocked, 0)`。站位错误仍必须修数据，不能用地面回退远程触发任务。
- 静态连通分量随 `Navigation` 实例缓存；换图或机关改变碰撞后重建。普通直线点击不做连通分量搜索。动态危险可能暂时切断地面，此时仅在一次路线失败后搜索当前可达侧，不把危险永久缓存成墙，也不每帧全图遍历。
- 栅格边界附近允许 2×1 格的短连接，解决窄斜地板上“脚印实际能通过，却没有相邻格链”的离散误差。所有短连接和简化后路线仍通过相同的九点脚印、完整多边形边界交叉与动态危险检查；不通过缩小主角脚印、拆除家具或跨水来开路。
- 多边形顶点交叉判断加入 `1e-9` 参数容差。擦过精确角点的长线不能因 `u=-1e-16` 的舍入被错误放行，再被动画的短子线段拒绝；规划阶段即绕开角点，不通过放松逐帧碰撞来修正。

## DAY02 截图问题与修正

用户截图里的维修暗门已经打开，旧渲染仍按关闭态 `baked` 热区和单个 `depth=326` 在角色之后回贴背景。该热区横跨门洞，会把站在开放地砖上的角色下半身切掉；一个固定 Y 值也无法描述墙底的斜边。

现在基础图与状态贴片、静态绑定物先绘制。玩家、动物和跟随宠物分别按自己的脚底裁剪，遮挡只影响该角色的像素，不回贴背景抹掉其他角色，不使用“透明主角”掩盖错误。

公共接口在 `src/campaign/occlusion.ts`：

- `collectSceneOccluders(world, entities, flags)`：收集生效遮挡；打开的门或已拆墙不复用旧关闭热区。
- `contactDepthAt(contactLine, x, fallback)`：沿真实地面接触折线插值。
- `drawWithOcclusion(ctx, foot, occluders, draw)`：只裁去处于角色前方的轮廓；多个重叠遮挡分别相交，避免一次奇偶裁剪产生穿墙孔洞。
- `isPointOccluded(point, foot, occluders)`：供动态角色鼠标命中采用相同可见性规则。

`ObjectVisual.contactLine`、`WorldOccluder.contactLine` 均使用 1600×900 世界坐标；遮挡可用 `requires` / `unless` 随机关状态生效。旧水平 `depth` 是兼容回退，不代表已完成全部装饰物的精细分层。

DAY02 新增/修正：

1. 已开门左侧短墙与右侧壁板分为两块真实轮廓，各自标地面斜接触线；门中间不再留一个关闭态遮挡面。末轮实机发现右侧固定壁板误限为开门后才遮挡，已改为两态共用；左侧开门图改画了墙帽，因此关闭时只使用原画共同的下部墙身轮廓，开启后换为短墙完整轮廓，不把改画后的上沿或门中空地套到闭态。
2. 两侧残墙增加实际地面脚印，东北墙柱仍阻挡；没有把可见壁板或墙顶开放为地面。
3. 电气柜、屏幕、墙上面板和门框增加斜支撑线，避免统一按中心深度切人。
4. 西侧工位抽屉前的斜通道通过短栅格连接恢复可达，桌椅碰撞数据不因该抽屉缩小。
