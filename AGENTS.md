# Project working agreement

- `docs/GAME_DESIGN.md` is the source of truth for the core loop and progression.
- `docs/LEVEL_BLUEPRINTS.md` owns level narrative, items, clues, codes, hazards, and endings.
- `docs/ART_DIRECTION.md` owns visual and UI constraints.
- Record material product decisions in `docs/DECISIONS.md`.
- Update `docs/ROADMAP.md` and `CHANGELOG.md` when implementation status changes.
- Keep the always-visible HUD minimal: day/time, objective, backpack button, and five quick slots.
- Preserve fair hazard telegraphs. Every lethal hazard needs a readable warning and a viable safe response.
- Concept images are references, not production-ready maps or sprites.
- Use deterministic game logic where possible so failures can be reproduced.
